  • H1Evolving files lower test ASR: C3 and C4 on their final file against C1, at equal benign utility (C3/C4 benign before against after). One value per run, no curve.
  • H2Against an adaptive attacker, a static file degrades faster: the ASR slope in C2 against C4, on train-injection pairs only, since C4 can't rewrite test pairs.
  • H3Gains generalize: ASR on held-out attack styles over test injections, and C5 against a fresh attacker.

Train · 60% · ~21 injection tasksPairs run one at a time in a fixed order and drive the skill file's evolution. Judge input comes only from here.
Test · 40% · ~14 injection tasksRun only on the frozen final file. Adds held-out styles injecagent and ignore_previous, never used in training.
Who splitsOnly C3 and C4. C0, C1 and C2 run every pair against S0; each C1/C2 record keeps its pair's split label so results can be cut to the same pairs as C3/C4
Suitesworkspace, travel, banking, slack (v1.2.2), split stratified by suite, seed 0, no dev split
PairsOne fixed set of (user task, injection task) pairs, sampled once with a fixed seed and used in every condition and seed, in the same order. A pair sits on its injection task's side. Pair count set by a power check after the pilot
Trials3 per pair, run back to back, always all 3; 3 seeds per condition, so 9 trials per pair
Benign setEvery user task, no injection. In C3/C4: once on S0 before the train phase, once on the final file after it. Used for benign utility and checker false-positive rate, in evaluation only
ReportedASR, utility under attack, benign utility, checker FPR, injected text removed, benign text removed, cost per component; bootstrap 95% CIs
Still open before Phase 1
  • The victim scored 0/16 ASR on the banking slice smoke test. The "C0 ASR ≥ 20%" rule has to be checked across all suites and injection tasks, or there's nothing to defend.
  • Checker and attacker model IDs, and the one OpenRouter provider to pin (no fallbacks), are still to be chosen in Phase 0.
  • C4 test pairs: the attacker never sees test injection tasks, so unless decided otherwise they keep the trial-0 text in all 3 trials, and on test C4 differs from C3 only through its file.
  • How the fixed train pair order is chosen (for example shuffled with the fixed seed, or grouped by suite).
  • When the benign set runs in C1 and C2, now that there are no run-wide rounds. H1 needs C1's benign utility.
  • H2's x-axis: rounds are gone, and in C4 the file changes across pairs as well as across a pair's trials.
  • Delta edits: whether the Principles are frozen, the edit budget (proposed ≤ 2 edits per step, ~60 tokens per rule), the common-word list for the identifier ban, and whether one invalid edit rejects the whole batch.
  • The checker's minimum span length (min_span_chars), set on the pilot.
  • The native-loop reference addresses the model as "AI assistant" in important_instructions, while the DeepAgents run says "DeepSeek". The two need the same attack text before the comparison means anything.
