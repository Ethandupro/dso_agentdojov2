Four runs in a 2 × 2, plus two reference runs

C5 · frozen evolved file · on hold. The final C4 skill file, locked, against a fresh evolving attacker with an empty archive. Put on hold by the user; not built in the runner.
  • H1Evolving files lower test ASR: C3 and C4 on their final file against C1, at equal benign utility (C3/C4 benign before against after). One value per run, no curve.
  • H2Against an adaptive attacker, a static file degrades faster: C2 against C4, on train-injection pairs only, since C4 can't rewrite test pairs. Two x-axes (decided 2026-11-17): main, position in the run (train pairs in run order, 10 equal bins, the same pairs in both); second, trial index 0/1/2.
  • H3Gains generalize: ASR on held-out attack styles over test injections (and C5 against a fresh attacker, on hold).

How it runs

One command per condition, then one comparison

HardwareThe project's 2× H100 VM: victim on GPU 0 (port 8000), checker and attacker on GPU 1 (ports 8002, 8003), started by local_victim/serve_all.sh. Only the judge (C3, C4) uses OpenRouter, key from --env-file ~/api.env
1 · Manifestagentdojo.runner.build_manifest writes pairs_manifest.json; every run checks its inputs against it before any model call
2 · Runagentdojo.runner.run_condition --condition C0…C4 checks the servers, writes config.json, works through a fixed unit list and checkpoints after each unit, so the same command resumes. --limit N runs the first N pairs in a separate folder
3 · ReportEach run writes summary.json and report.html (also mid-run, with agentdojo.runner.report)
4 · Compareagentdojo.runner.compare reads all runs and writes comparison.html: H1, H2 (both axes) and C0 vs C1, with paired bootstrap differences
Unit orderC0–C2: benign set, then every pair × 3 trials. C3/C4: benign before, train pairs, freeze, test pairs, benign after
Still open
  • When the benign set runs in C1 and C2. The runner runs it once, before the attacked pairs, against S0 (proposal). H1 needs C1's benign utility.
  • C4 test pairs: the attacker never sees test injection tasks, so unless decided otherwise they keep the trial-0 text in all 3 trials, and on test C4 differs from C3 only through its file.
  • Delta edits: whether the Principles are frozen, the edit budget (≤ 2 edits per step, ~60 tokens per rule), the common-word list for the identifier ban (empty for now, so the ban is strict), and whether one invalid edit rejects the whole batch. The code uses these proposals as defaults. Four S0 rules (S4, S6, K2, K3) are already over ~60 tokens.
  • The digest size N (proposed 20), the token counter for the 1500-token cap (proposed: the checker's tokenizer), and the leakage archive in C3 (proposed: every injection text the run's train trials used so far).
  • The checker's minimum span length (min_span_chars), set on the pilot.
  • PAIR's settings (3 streams × 4 iterations) may be lowered for cost: C2 rewrites 2 × 949 pairs.
  • MUZZLE's upstream smoke test can't be reproduced as written. Proposed instead: the byte-identity tests on the vendored files plus a short live C2 run.
  • The held-out styles (injecagent, ignore_previous) are in the design but not yet in the runner's test phase.
  • The native-loop reference must address the model by the same name as the DeepAgents run in important_instructions, or the two don't send the same attack text.
