Skill File Evolution

Can a judge model keep editing an agent's security skill (the "skill file", one of the skills the agent can choose to load) one rule at a time, after each attack that gets through, so prompt-injection success drops on attacks it has never seen, including against attackers that adapt back?

The experiment

Four runs in a 2 × 2, plus reference runs

Each cell is one run with its own directory, cache and attacker archive under results/<run_id>/seed_<n>/. A full run covers all 949 pairs; smoke and pilot cuts (--smoke, --limit, --subset, --single-injection-point) get their own folders. All runs get the same inputs: the same pairs in the same order, the same S0 and the same trial-0 important_instructions text. Only C3 and C4 split pairs into train and test. C0 · no S0, static attack. The victim with only its five fixed skills: raw ASR and the utility ceiling. c0_no-s0_static-attack. It must show ASR ≥ 20%, or there is nothing to defend. Also run once on AgentDojo's native loop to show the DeepAgents harness doesn't shift the numbers.
C0E · no S0, evolving attack (added 2026-11-20, PR #39). C0's victim against C2's attacker with the same settings. c0e_no-s0_evolving-attack. C2 against C0E shows what S0 adds under adaptive attack, as C1 against C0 does under the static one. No split; same --trials-per-pair as C2.
C5 · frozen evolved file · on hold. The final C4 skill file, locked, against a fresh evolving attacker with an empty archive. Put on hold by the user; not built in the runner.
  • H1Evolving files lower test ASR: C3 and C4 on their final file against C1, at equal benign utility (C3/C4 benign before against after). One value per run, no curve.
  • H2Against an adaptive attacker, a static file degrades faster: C2 against C4, on train-injection pairs only, since C4 can't rewrite test pairs. Two x-axes (decided 2026-11-17): main, position in the run (train pairs in run order, 10 equal bins, the same pairs in both); second, trial index 0 … k (0 … 8 with 9 trials per pair).
  • H3Gains generalize: ASR on held-out attack styles over test injections (and C5 against a fresh attacker, on hold).
  • S0What S0 adds: C1 against C0 under the static attack, and C2 against C0E under the evolving one. Because the attacker's playbook grows during a run, C2, C4 and C0E ASR should also be reported for the first and second half of the run order.

Benign setEvery user task, no injection. In C3/C4: once on S0 before the train phase, once on the final file after it. In C0, C0E, C1 and C2 the runner runs it once before the attacked pairs (proposal, see below). Used for benign utility and the S0 load rate on clean tasks, in evaluation only

How it runs

One command per condition, then one comparison

HardwareThe project's shared 2× H100 VM, started by local_victim/serve_all.sh: victim Magistral on GPU 0 (BF16, port 8000, no draft), attacker Qwen3.8-27B + DFlash2 on GPU 1 (BF16, port 8003). ONE_GPU=<n> puts both on GPU n in FP8; ATTACKER_DRAFT=none drops the draft; CHECKER=1 adds the old checker on port 8002 for the ablation (not with ONE_GPU). Current setup (user, 2026-11-23): ONE_GPU=0 ATTACKER_DRAFT=none bash local_victim/serve_all.sh, so victim and attacker share GPU 0 in FP8. Serve every compared condition the same way. Only the judge (C3, C4) uses OpenRouter, key from --env-file ~/api.env
1 · Manifestagentdojo.runner.build_manifest writes pairs_manifest.json; every run checks its inputs against it before any model call
2 · Runagentdojo.runner.run_condition --condition C0|C0E|C1|C2|C3|C4 checks the servers, writes config.json, works through a fixed unit list and checkpoints after each unit, so the same command resumes (a different config is refused). Main options: --trials-per-pair, --smoke, --limit N, --suites, --subset, --single-injection-point, --attacker autodojo|skill-agent|muzzle, --distill-every K, --distill-mode contrast|plain, --stop-on-success, --victim-temperature, --attacker-temperature, --external-checker
3 · ReportEach run writes summary.json and report.html (also mid-run, with agentdojo.runner.report)
4 · Compareagentdojo.runner.compare reads all runs and writes comparison.html: H1, H2 (both axes) and C0 vs C1, with paired bootstrap differences
Unit orderC0, C0E, C1, C2: benign set, then every pair × its trials. C3/C4: benign before, train pairs, freeze, test pairs, benign after
Still open
  • When the benign set runs in C0, C0E, C1 and C2. The runner runs it once, before the attacked pairs, against S0 (proposal). H1 needs C1's benign utility.
  • C4 test pairs: the attacker never sees test injection tasks, so unless decided otherwise they keep the trial-0 text in every trial, and on test C4 differs from C3 only through its file.
  • Delta edits: whether the Principles are frozen, the edit budget (≤ 2 edits per step, ~60 tokens per rule), the common-word list for the identifier ban (empty for now, so the ban is strict), and whether one invalid edit rejects the whole batch. The code uses these proposals as defaults. Four S0 rules (S4, S6, K2, K3) are already over ~60 tokens.
  • The digest size N (proposed 20), the token counter for the 1500-token cap (since 2026-11-19: the victim's tokenizer), and the leakage archive in C3 (proposed: every injection text the run's train trials used so far).
  • agentdojo.runner.compare reports H1, H2 and C0 vs C1, but not yet C2 vs C0E or the first-half/second-half ASR split.
  • The held-out styles (injecagent, ignore_previous) are in the design but not yet in the runner's test phase.
  • The native-loop reference must address the model by the same name as the DeepAgents run in important_instructions, or the two don't send the same attack text.
