Data

Split by injection task, so the judge can't memorize the goal

Train · 60% · ~21 injection tasksAttacks: important_instructions or the evolving attacker. Judge input and gate replays come only from here.
Test · 40% · ~14 injection tasksAdds held-out styles injecagent and ignore_previous, never used in training.
Suitesworkspace, travel, banking, slack (v1.2.2), stratified split, seed 0
Benign setEvery user task, no injection. Used for false-positive rate and benign utility, in the gate and in evaluation
Per roundA fixed number of (user task, injection task) pairs per split, fixed per-round seed. Pair count set by a power check after the pilot
ReportedASR, utility under attack, benign utility, checker FPR, injected text removed, benign text removed, cost per component; bootstrap 95% CIs
Still open before Phase 1
  • The victim scored 0/16 ASR on the banking slice smoke test. The "C0 ASR ≥ 20%" rule has to be checked across all suites and injection tasks, or there's nothing to defend.
  • Checker and attacker model IDs are still to be chosen against the OpenRouter catalogue.
  • Checker prompt, skill file v0, the SuperRed ports and the round runner aren't built yet. The DeepAgents victim is ready for them: the runner plugs the checker in through tool_middleware_factory.
  • The native-loop reference addresses the model as "AI assistant" in important_instructions, while the DeepAgents run says "DeepSeek". The two need the same attack text before the comparison means anything.
